# Quiet expected non-SCCM-client root\CCM namespace error in local collector

On a Windows box that is local admin but NOT an SCCM client, root\CCM does not exist. _wmi_ccm() in collectors/local.py currently connects straight to root\CCM, catches the resulting WBEM_E_INVALID_NAMESPACE at ERROR level (with traceback under --debug), which cries wolf for an expected condition. Fix: pre-check by connecting to root, enumerating child namespaces (__NAMESPACE), and only connecting to root\CCM when CCM is present. Absent -> INFO skip, no traceback. Cannot reach root / enumeration fails -> ERROR (genuine WMI problem). Connected -> INFO as today.
