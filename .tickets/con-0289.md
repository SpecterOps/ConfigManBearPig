# Integration fixtures cannot be gated on possible-edges, so low-priv + --disable-possible-edges reports 4 false failures

The built-in integration fixture set can gate a case on privilege (requires_privilege) but NOT on whether possible/assumed edges are enabled. There is no requires_possible_edges flag -- grep over src/openhound_sccm/integration/ returns requires_privilege only.

That gap makes the LOW-PRIVILEGE + --disable-possible-edges combination report four failures against a graph that is behaving exactly as designed:
  edge-samehostas-clientdevice-to-computer-ps1-dev  (not found)
  edge-samehostas-computer-to-clientdevice-ps1-dev  (not found)
  edge-hasclient-ps1-site-ps1-dev                   (not found)
  node-clientdevice-count                           (not found)

Why the graph is right: a device with a CmRcService SPN in AD but no confirmed SCCM enrollment is emitted as a POSSIBLE SCCM_ClientDevice, and --disable-possible-edges suppresses exactly those (README, 'Assumed vs. confirmed graph content'). At PRIVILEGED, ps1-dev is a CONFIRMED client because AdminService/WMI enumerate it, so pe-off keeps it and these four cases pass -- ab-priv-pe-off shows 76 passed / 1 failed with none of the four present. At LOW privilege the same device is only inferred, so pe-off correctly removes it and the four cases have nothing to match.

Confirmed by graph comparison rather than assumed: openhound-compare with pe-off as baseline and pe-on as candidate reports 0 regressions in both privilege tiers, i.e. pe-on is a strict superset -- 8 additions privileged (one possible client device plus its HasClient/SameHostAs edges and the assumed/assumptionBasis property kinds) and 96 additions low-privilege (many more devices are inferred rather than confirmed there). --disable-possible-edges is tightening-only in both tiers, as documented.

This combination appears never to have been exercised: there is no --disable-possible-edges output anywhere under out/ before this run, and dev/ab_matrix.py plans pe-off cells but no pe-off baseline zips exist for it to diff against.

## Acceptance Criteria

A fixture case can declare that it depends on possible/assumed content, and the runner skips such cases when the run was collected with --disable-possible-edges (the flag is persisted in collection_settings at collect time, so the graph itself records which mode produced it). A low-privilege --disable-possible-edges run reports 0 failures against the mayyhem lab. Baseline zips exist for the pe-off cells so dev/ab_matrix.py can run its full matrix.
