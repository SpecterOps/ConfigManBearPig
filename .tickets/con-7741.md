# SMS Provider probe is skipped when port 80 is filtered despite being HTTPS-only

collectors/http.py: the SMS Provider probe is HTTPS-only, but it sits behind the per-protocol connection_failed short-circuit that the port-80 MP/DP probes drive. So a host with port 80 filtered and 443 open loses its SMS Provider role tag even though the provider is perfectly reachable. Consequence observed indirectly during con-6198: the SMS Provider tag feeds SCCM_CoerceAndRelayToAdminService's coercionVictimAndRelayTargetPairs list, so losing it silently truncates that edge's pair list rather than failing loudly. Fix direction: move the sms_provider() call outside the per-protocol loop, or reset/ignore connection_failed before it, so an HTTPS-reachable provider is still detected when HTTP/80 is filtered. Low priority: it needs an unusual firewall posture (80 closed, 443 open) to bite, and no mayyhem host currently has it.

## Acceptance Criteria

A host with port 80 filtered and 443 serving the AdminService still gains its SMS Provider role tag; a regression test covers the filtered-80 case.
