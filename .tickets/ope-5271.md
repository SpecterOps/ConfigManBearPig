# Fix invalid server address on NetBIOS-prefixed account resolution (NAA, sccm_push)

resolve_principal builds an LDAP search base from a NetBIOS domain hint (e.g. MAYYHEM\networkaccess -> base DC=MAYYHEM), an invalid single-label naming context. AD returns a referral; ldap3 auto_referrals chases it and raises LDAPSocketOpenError: invalid server address. Only NAA + sccm_push hit this (NetBIOS-prefixed); FQDN/SID principals build valid bases. Fix: (1) skip LDAP search for single-label domain hints in _ldap_resolve; (2) disable auto_referrals on the ldap3 Connection in ad.py.

## Notes

**2026-06-12T17:13:32Z**

Fixed in two spots (both in sccm/sccm):
1. context.py _ldap_resolve — skip the LDAP search when the domain hint is single-label (no dot). DC=<NetBIOS> is never a valid naming context, so resolution now falls through to the FQDN domain in the try-list. Logs at debug.
2. clients/ad.py _open_connection + _open_current_user_ntlm_connection — set auto_referrals=False so ldap3 no longer chases referrals/continuation references into unreachable servers (the actual source of LDAPSocketOpenError: invalid server address).
