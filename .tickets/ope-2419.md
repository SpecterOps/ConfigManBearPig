# Remove direct BloodHound CE upload from the published packages

Removed the direct BloodHound CE upload feature from both published packages before the PyPI publish, archiving it in the fork at bloodhound-upload/ (a fork-root directory, so neither 'git archive HEAD:sccm/sccm' nor 'git archive HEAD:openhound-collector-common' can carry it into a public repo). Rationale: it existed to shorten the develop/verify loop and stopped paying for itself once the port was feature-complete -- every configmanbearpig user would have carried an HTTP client, HMAC/Bearer signing, a zip bundler and a schema mutator for a workflow most operators do not use, and openhound-collector-common needed 'requests' solely for it. OUT of the library: the whole self-contained bloodhound/ subpackage (6 modules) + 6 tests + the requests dependency. OUT of the collector: bloodhound_schemas.py, bloodhound_upload.py, 3 tests, _resolve_upload_mode + _dispatch_bloodhound_upload, and all 16 CLI options (8 on collect sccm, 8 on convert sccm). ARCHIVED: all of the above plus cli_integration.py (the main.py code was inline, so it is extracted verbatim with a map of where each piece sat), the 2 design plans, ARCHITECTURE 15, and both removed README sections. DELIBERATELY UNCHANGED: convert sccm stays hand-registered (still carries --lookup-file/--progress; the decorator has no flag seam, so app.converter is still assigned and openhound is still a declared dependency for that reason); both schema JSON files stay in the package (integration/__init__.py reads schema_SCCM.json at runtime for the test kit's coverage check, schema_MSSQL.json ships as an operator deliverable); --disable-possible-edges stays on collect where it changes the graph. REMOVED from convert: --disable-possible-edges, which was a no-op there in all but name -- possible edges are gated during preprocess (transforms._read_disable_possible), so by convert time the decision is already in the lookup DB and the flag's only remaining effect was flipping is_traversable in the schema the upload pushed. Also: no shipped doc references the private archive, because ARCHITECTURE.md and PUBLISHING.md travel to the public repo while bloodhound-upload/ does not -- the removal narrative lives in bloodhound-upload/docs/removal-record.md and the public changelog states only the fact.

## Acceptance Criteria

No bloodhound/upload code, CLI option, test or doc section in either published package; nothing under sccm/sccm or openhound-collector-common references bloodhound-upload/. Archive holds 24 files including a re-wiring checklist. Verified: both commands bind, collect keeps --disable-possible-edges and convert is down to --lookup-file/--progress, ruff+mypy clean in both packages, full collector suite 890 passed / 5 skipped, library 81 passed, and a live --run-all collect produced a graph fingerprint identical to the pre-session baseline (148 nodes / 454 edges).
