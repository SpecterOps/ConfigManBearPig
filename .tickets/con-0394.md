# Positively identify a secondary site or site server as a plain domain user

A SECONDARY site is currently only identifiable via LDAP (mSSMSManagementPoint capabilities) or privileged AdminService/WMI (SMS_SCI_SiteDefinition.SiteType). Neither reaches a real secondary at low privilege.

MEASURED 2026-08-01 against the mayyhem lab. The AD System Management container holds ONLY:
  SMS-Site-PS1                    mSSMSSite
  SMS-Site-CAS                    mSSMSSite
  SMS-MP-PS1-PS1-MP.MAYYHEM.COM   mSSMSManagementPoint
No mSSMSSite and no mSSMSManagementPoint object exists for SEC, so ldap_management_points_raw holds exactly one row (PS1) and the ported capabilities classifier in collectors/ldap.py _parse_mp_capabilities has no SEC input. site_hierarchy at low privilege therefore has SEC with parent_site_code NULL and site_type NULL, versus (PS1, 1) when privileged.

Consequence: the two secondary-site rules added under this work stay correctly silent at low privilege, because both gate on a positively known site_type = 1:
  - node_mssql_login parent-primary arm (the parent primary site servers are sysadmin on a secondary site database)
  - edge_local_admin_required parent-primary -> child-secondary arm
Per @_Mayyhem 2026-08-01: do not infer these from negative evidence. Emit only what can be confirmed or positively inferred.

INVESTIGATE what a plain domain user CAN reach that POSITIVELY identifies a secondary site or secondary site server. Candidates to test, not yet validated:

1. COMBINED HOST FINGERPRINT (@_Mayyhem 2026-08-01). Look for a single system that simultaneously:
   - hosts BOTH the Management Point and Distribution Point roles for ANOTHER site that might be its parent (e.g. roles tagged @PS1 on a host that is not a PS1 site server)
   - runs the MSSQL service (1433 answering, or an SMB/registry signal)
   - is a site server for a DIFFERENT site (e.g. SMS Site Server@SEC)
   That triple is close to a signature: Microsoft REQUIRES a secondary site database to be co-located on the secondary site server, and a secondary commonly proxies MP/DP duty for its parent. If the combination proves specific enough it would identify both the secondary AND its parent in one shot, which is exactly what both new arms need. Validate against a topology where a primary site server also happens to run SQL, to check the false-positive rate.
   Observed today at low privilege for ps1-sec: SMS Site Server@SEC, SMS Distribution Point@SEC, SMS Management Point@SEC, SMS Management Point@PS1, and mssql_server_instances port_open true with has_mssql_spn false.

2. MP HTTP ENDPOINTS. mSSMSCapabilities is the same ClientOperationalSettings XML an MP serves to clients. Determine whether any anonymous or domain-user MP endpoint returns it (MPLIST, MPKEYINFORMATION, MPCERT, or the client policy path). If it does, _parse_mp_capabilities can be reused verbatim on an HTTP-discovered MP with no new inference rule at all. This is the cleanest possible outcome.

3. REGISTRY. Which HKLM SMS keys carry site type or parent, and which are readable by a non-admin. Today ps1-sec SMS keys measured admin-gated: 0 empty-key firings low-priv versus 1 privileged.

4. SMB SHARE SET. A secondary exposes SMS_<code> and SCCMContentLib$; check whether the share SET or a share comment distinguishes a secondary from a primary.

5. NO SMS PROVIDER (weaker, negative). Secondary sites have no SMS Provider. Only admissible with a control: the same run must have observed an SMS Provider for some other site, proving the probe works. Recorded for completeness; lower priority than the positive signals above.

Whatever lands must key the two existing arms without loosening their site_type = 1 gate: the gate is the mirror image of _NON_SECONDARY_SITE_TYPE_SQL and an unknown type must keep excluding.
