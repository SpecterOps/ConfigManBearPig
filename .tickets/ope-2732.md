# Fix RemoteRegistry trigger-start race + double-logoff in registry collector

First RemoteRegistry connect often fails with STATUS_PIPE_NOT_AVAILABLE because the target's RemoteRegistry service is trigger-started and the \winreg pipe isn't listening yet on the first open. Second attempt works. Fix: retry the winreg bind (3 tries, 1.5s apart) only on STATUS_PIPE_NOT_AVAILABLE, mirroring native OpenRemoteBaseKey behavior. Also fix double-logoff in _RegistryProbe that emits a spurious STATUS_USER_SESSION_DELETED ERROR by letting __exit__ own the single logoff.
