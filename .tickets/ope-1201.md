# node_mssql_server drops registry-only SQL servers (coalesce port VARCHAR vs INTEGER_LITERAL)

preprocess sccm logs: transform 'node_mssql_server<-remoteregistry_mssql_servers' failed: Binder Error: Cannot mix values of type VARCHAR and INTEGER_LITERAL in COALESCE. Root cause: the remote registry stores SQL TcpPort as a REG_SZ string ('1433'), so dlt types the column VARCHAR, but arm 3 coalesced it against the integer literal 1433 (copied from the EPA-scan arm, whose port genuinely is INTEGER). safe_execute swallows the non-catalog error and drops the whole arm, so every registry-only SQL server (not an SCCM site DB, not EPA-scanned) was silently missing from node_mssql_server. Fix: arm 3 now uses coalesce(port,'1433') (string default, matching arm 1's idiom) and _ensure_columns declares port VARCHAR. Verified end-to-end: registry-sourced servers went 0->2 in the built lookup.duckdb; new regression test test_registry_only_server_kept_with_string_port; 46 mssql+transforms tests pass.
